Guide Intention

Construisez votre première interface, étape par étape.

Ce guide part de zéro, explique chaque décision et vous laisse modifier de vrais exemples Intention directement dans la page.

Intention transforme des descriptions lisibles en composants Web réactifs. Vous déclarez les données, les composants et les interactions ; le framework génère le rendu, maintient l'état synchronisé et utilise vos Web Components pour le design.
À qui s'adresse ce guide ?Aux personnes qui découvrent le frontend comme aux développeurs expérimentés qui veulent produire une interface sans JSX, hooks ou balisage à fermer.

Démarrage rapide

Une application locale en trois commandes.

Intention demande Node.js 20 ou plus récent. La commande init génère une application complète avec ses routes, pages, composants, assets et son design de départ.

Pré-requisVérifiez Node.js avec node --version. Toute version 20 ou plus récente convient.
Terminalintent init mon-projet cd mon-projet npm run dev
Ouvrez ensuite http://localhost:4173. Le serveur compile les fichiers .intent, sert les pages en SSR et recharge l'application après chaque modification.
Initialisezintent init crée une base claire sans assistant complexe.
Lanceznpm run dev démarre le compilateur et le serveur local.
ModifiezCommencez dans pages/Home.intent et enregistrez le fichier.

Tutoriel

Un compteur réactif sans balisage.

Un composant rassemble son état et son interface. var crée une donnée réactive ; on click décrit l'interaction exactement là où elle se produit.

Dans l'éditeur ci-dessous, remplacez la valeur initiale, modifiez les libellés ou ajoutez un second message. Chaque changement est analysé par le vrai parseur Intention puis exécuté dans un aperçu isolé.
Compteur interactifEssayez count = 10, changez le texte ou ajoutez une condition.component App: var count = 0 computed doubled = count * 2 heading "Mon compteur" row: button "−": disabled if count == 0 on click: count = count - 1 text count button "+": on click: count = count + 1 message "Valeur doublée :" message doubled
Le point importantIl n'existe ni fonction de rendu ni appel manuel pour rafraîchir la page. Une affectation suffit : Intention recalcule seulement ce qui dépend de count.

Architecture

Des fichiers rangés comme dans un framework classique.

Le point d'entrée configure l'application. Les pages, composants et assets sont découverts automatiquement, sans liste d'imports à maintenir.

Arborescencemon-projet/ ├── app.intent ├── routes.intent ├── pages/ │ ├── Home.intent │ └── NotFound.intent ├── components/ │ └── ProductCard.intent ├── design/ │ └── design.js ├── assets/ └── package.json
app.intentapplication = "Mon application" design = "./design/design.js" start = Home
app.intent porte la configuration globale. routes.intent associe les URL aux composants de page. Chaque autre fichier .intent peut déclarer un ou plusieurs composants réutilisables.

Le langage

Une intention par ligne, deux espaces pour entrer dans un bloc.

Les deux-points ouvrent un bloc. Les paramètres sont nommés et séparés par des virgules. Les guillemets indiquent un texte littéral ; sans guillemets, Intention évalue une expression.

syntaxe.intentcomponent ProductCard: input title = "Produit" input price = 0 card: heading title message price button(variant: "brand", disabled: false) "Ajouter": on click: emit selected with title
"texte"Valeur littéraleLe contenu est affiché exactement comme il est écrit.heading "Bienvenue"
expressionValeur dynamiqueUne variable ou un calcul est évalué au rendu.message total * quantity
:Bloc enfantLa ligne suivante avance de deux espaces.button "Ajouter":

Réactivité

var change, computed suit automatiquement.

Utilisez var pour une valeur locale modifiable. Utilisez computed pour une valeur dérivée : elle est recalculée depuis l'état courant, sans dépendances à déclarer.

price.intentcomponent Price: var quantity = 1 var unitPrice = 12 computed total = quantity * unitPrice message "Total" heading total button "Ajouter une unité": on click: quantity = quantity + 1
Choisir le bon mot-clévar pour une source de vérité, computed pour une valeur que l'on peut toujours retrouver à partir d'autres données, memory pour une information technique qui ne doit pas provoquer de rendu.

Composition

Construisez de petits blocs qui se lisent seuls.

input définit le contrat public du composant. Le parent transmet les valeurs avec des paramètres nommés. slot choisit où afficher le contenu fourni par le parent.

components/Panel.intentcomponent Panel: input title = "Section" card: heading title slot component Home: Panel(title: "Profil"): message "Contenu fourni par Home" button "Modifier"
Les composants Intention deviennent des Custom Elements préfixés par intent-. Ils peuvent donc être utilisés dans une autre application Web et conserver leur état, leurs événements et leur encapsulation.

Interactions

L'événement est placé sous l'élément concerné.

on click, on change et on submit regroupent les actions déclenchées. if et else rendent les variantes explicites au même niveau que le reste de l'interface.

Condition interactiveChangez les messages ou ajoutez un second bouton.component App: var connected = false heading "Mon espace" if connected: message "Vous êtes connecté." else: message "Connectez-vous pour continuer." button "Changer d'état": on click: toggle connected
form.intentcomponent ContactForm: var email = "" form: input "Votre e-mail": bind email button "Envoyer": disabled if email == "" on click: notify "Message envoyé"

Collections

each répète, where filtre, key conserve l'identité.

Chaque élément de la collection reçoit un nom local. index indique sa position. Une key stable permet à Intention de préserver le bon état lors d'un tri ou d'une suppression.

Liste modifiableCliquez sur une tâche pour la retirer du tableau.component App: var tasks = ["Écrire", "Tester", "Publier"] heading "À faire" each task in tasks: card: heading task button "Terminer": on click: tasks -= task if tasks.length == 0: message "Tout est terminé !"
filtrer.intenteach product in products where product.available key product.id: ProductCard(product: product, key: product.id)

Placement

La grille annonce sa capacité, les enfants demandent leur place.

columns fixe le nombre maximal de colonnes. minimum indique la largeur souhaitée avant le repli mobile. width et height expriment l'occupation de chaque composant.

Grille en directEssayez columns: 2, gap: 32 ou changez les largeurs.component App: heading "Tableau de bord" grid(columns: 3, minimum: 150, gap: 12): card(width: 2): heading "Activité" message "Vue principale" card: heading "Équipe" message "12 membres" card: heading "Tâches" message "8 ouvertes"
Responsive sans media queryLorsque l'espace devient trop étroit, Intention réduit le nombre de colonnes et replace les éléments dans leur ordre naturel.

État avancé

Partagez sans Provider, persistez sans plomberie.

shared rend une valeur disponible dans tous les composants. action nomme une transition métier, do l'exécute et persist restaure automatiquement une valeur après rechargement.

cart.intentshared cart = [] component AddButton: input product = {} action add(item): cart += item notify "Ajouté au panier" button "Ajouter": on click: do add with product component Preferences: persist theme = "light"
sharedDisponible partoutUne source de vérité réactive pour plusieurs composants.shared cart = []
action / doTransition nomméeRegroupe plusieurs changements sous un nom métier.do add with product
persistConservé localementLa valeur survit à la fermeture et au rechargement.persist theme = "light"

Synchronisation

Chargez une API et dialoguez avec le navigateur.

load expose automatiquement le résultat, le chargement et l'erreur. Les effets nomment clairement les moments du cycle de vie. ref permet de focaliser, faire défiler ou piloter un élément.

catalog.intentcomponent Catalog: load products from "/api/products" if productsLoading: message "Chargement…" else: if productsError != "": message productsError else: each product in products key product.id: ProductCard(product: product, key: product.id)
effects.intentcomponent Search: var query = "" on mount: log "Recherche prête" on change of query: log query input(ref: "searchField") "Rechercher": bind query button "Écrire": on click: focus searchField

Pages

Une configuration de routes, du HTML déjà rendu.

Chaque route pointe vers un composant portant le même nom. Les routes statiques sont pré-rendues ; les paramètres dynamiques deviennent directement des inputs de page.

routes.intentroutes: Home: "/" Documentation: "/docs" Product: "/products/:id" NotFound: "*" component Product: input id = "" heading id button(href: "/docs") "Retour au guide"
Un bouton avec href utilise automatiquement la navigation cliente après le premier chargement. L'historique, les boutons précédent/suivant et les ancres restent natifs.

Design

Le langage décrit l'interface, vos composants définissent son apparence.

Une petite table de correspondance relie button, card ou input aux Custom Elements de votre bibliothèque. Sans correspondance disponible, Intention revient à l'élément HTML natif.

design.jsexport default { button: { tag: "acme-button", properties: { disabled: "inactive" }, events: { clicked: "activate" } }, card: { tag: "acme-card" } };
Progressive enhancementLe contenu SSR reste lisible avant le chargement JavaScript. Une fois le design system prêt, les éléments sont activés et les interactions prennent le relais.

Workflow

Autocomplétion pendant l'écriture, fichiers statiques à la fin.

L'extension VS Code connaît les mots-clés, les composants du projet, leurs inputs et leurs événements. La compilation de production génère le HTML SSR, le runtime et les assets dans dist/.
